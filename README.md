# URL Shortener

Небольшой сокращатель ссылок на Go и PostgreSQL. Отправляешь длинный URL, получаешь короткую ссылку. По ней можно перейти на исходную страницу, а отдельным запросом — посмотреть число переходов.

Здесь я держу архитектуру простой: HTTP-обработчики, логика сокращения ссылок и репозиторий с SQL. Без авторизации, кэша и внешних API.

## Что умеет

- Создавать случайный шестисимвольный код и сохранять ссылку в PostgreSQL.
- Перенаправлять с короткого адреса через `302 Found`.
- Считать GET-запросы по ссылке и отдавать статистику.
- Проверять URL и тело запроса, обрабатывать конфликты кодов.
- Завершать текущие HTTP-запросы при остановке сервера.

Стек: Go 1.25+, `net/http`, PostgreSQL 16, `pgx/v5`. Docker Compose используется для локальной базы.

## Запуск

Нужны Go, Docker и Docker Compose.

```bash
git clone https://github.com/lumen-dev02/url-shortener.git
cd url-shortener
cp .env.example .env
docker compose up -d postgres
```

На новой базе примените обе миграции по порядку:

```bash
docker compose exec -T postgres psql -v ON_ERROR_STOP=1 -U shortener -d shortener < migrations/001_create_urls.up.sql
docker compose exec -T postgres psql -v ON_ERROR_STOP=1 -U shortener -d shortener < migrations/002_add_visits.up.sql
```

Если база осталась от предыдущей версии, нужна только `002_add_visits.up.sql`. Старые ссылки сохранятся, их счётчики начнутся с нуля. Миграции применяются вручную; повторно запускать `002` не нужно. Для отката сначала применяется `002_add_visits.down.sql` — он удалит счётчики, но не ссылки.

```bash
go mod download
set -a && . ./.env && set +a
go run ./cmd/api
```

Приложение само не читает `.env`, поэтому переменные нужно экспортировать. Адрес по умолчанию — `http://localhost:8080`.

## Попробовать API

Создать ссылку:

```bash
curl -i http://localhost:8080/api/v1/shorten \
  -H 'Content-Type: application/json' \
  -d '{"original_url":"https://example.com/articles/go"}'
```

Пример ответа `201 Created` (код будет другим):

```json
{
  "code": "aB3xYz",
  "short_url": "http://localhost:8080/aB3xYz",
  "original_url": "https://example.com/articles/go"
}
```

Подставьте полученный код:

```bash
CODE='<код из ответа>'
curl -i "http://localhost:8080/$CODE"
curl -sS "http://localhost:8080/api/v1/urls/$CODE/stats"
```

Первый запрос вернёт `302` с заголовком `Location`, второй — JSON с полями `code`, `original_url` и `visits`.

Счётчик увеличивается атомарным `UPDATE ... RETURNING`: параллельные запросы не затирают изменения друг друга. `HEAD` и запросы статистики его не увеличивают. Это число обработанных GET-запросов, а не уникальных посетителей: бот и повторный запрос тоже считаются. Если запись в БД не удалась, сервер ответит `500` вместо редиректа. Если клиент оборвал соединение после записи, переход всё равно может быть учтён.

| Маршрут | Результат |
|---|---|
| `POST /api/v1/shorten` | `201`, новая ссылка |
| `GET /{code}` | `302`, переход и увеличение счётчика |
| `HEAD /{code}` | `302`, без увеличения счётчика |
| `GET /api/v1/urls/{code}/stats` | `200`, ссылка и счётчик |
| `GET /healthz` | `200`, HTTP-сервер работает |

Невалидный JSON или URL — `400`, неизвестный код — `404`, неподдерживаемый метод — `405`, внутренняя ошибка — `500`. `/healthz` не проверяет соединение с БД.

## Настройки

| Переменная | По умолчанию |
|---|---|
| `HTTP_ADDR` | `:8080` |
| `DATABASE_URL` | обязательна, пример в `.env.example` |
| `BASE_URL` | `http://localhost:8080` |

`BASE_URL` — HTTP(S)-адрес без пути, логина, пароля, query и fragment. Например, `https://short.example`. Путь `/links` не поддерживается: приложение обслуживает короткие ссылки от корня. Пароль БД из примера подходит только для локального запуска.

## Как устроен код

```text
cmd/api/             конфигурация, запуск и остановка сервера
internal/handler/    маршруты, JSON и HTTP-ошибки
internal/service/    проверка URL, генерация кодов, переходы
internal/repository/ SQL-запросы
migrations/          создание таблицы и добавление счётчика
```

Код генерируется из букв и цифр через `crypto/rand`. Уникальность обеспечивает первичный ключ в БД. При конфликте сервис пробует новый код, максимум пять раз. Одинаковые исходные URL могут получить разные короткие ссылки.

Интерфейс репозитория позволяет тестировать сервис и обработчики без БД. Сам SQL проверяется интеграционным тестом на PostgreSQL.

## Тесты

```bash
go test -race ./...
go vet ./...
```

Для интеграционного теста нужна работающая база:

```bash
TEST_DATABASE_URL='postgres://shortener:shortener@localhost:5432/shortener?sslmode=disable' go test -race -count=1 ./...
```

Тест создаёт отдельную схему и удаляет её после выполнения; пользователю БД нужно право `CREATE`. Проверяются миграции, сохранение ссылок, конфликты кодов и параллельное увеличение счётчика. Без `TEST_DATABASE_URL` интеграционный тест пропускается. В GitHub Actions он запускается с PostgreSQL 16.

## Чего пока нет

Срока действия ссылок, пользовательских алиасов, аккаунтов и удаления ссылок. Статистика доступна без авторизации. Rate limiting тоже нет, поэтому для открытого публичного сервиса понадобится дополнительная защита.
